# 取り込みと打ち切り

- **合格**: `python scripts/orch.py accept <Issue番号> --scores <点数> --read <読んだ物の一覧のファイル>`（一覧はスキル `evaluate` の「読む物」で読んだ物。PR のコメントに残る）。ブランチを main に追いつかせ、索引を作り直し、`.task/` を消し、検査を確かめてから取り込む。symbols に変更があれば正本の IDB へ取り込む。
- **打ち切り**: `python scripts/orch.py reject <Issue番号> --reason <理由>`。
- **main との衝突**: 両方の変更を残すだけで済む衝突（同じ所への追記どうし）に限り、オーケストラが解いてよい。解いたら試験とビルドを通してからコミットし、何をどう解いたかを PR のコメントに書く。どちらかを選ぶ・書き直す必要がある衝突は、ワーカーに作業ツリーで解かせる。

## 取り込みの後

- 利用者に結果を見せる前（取り込みの前でも）に、オーケストラが `evaluate` の「読む物」と同じように確かめる。見た目なら全場面を拡大して見て、見つけた崩れは直させてから見せる。

- 報告の「記録すべき事実」（派生のワーカーから）は、解析の Issue にする。
- 報告の「新しいタグの提案」は、妥当なら `ac3ds-re/meta/tags.toml` に加える（次の取り込みと一緒に）。
- 消化が必要なカテゴリ（未消化が10件を超えた）があれば、消化の Issue を作る（スキル `consolidation`）。
- 名前や型が変わったら、派生リポジトリへの影響を `kb.py impact` で確かめる（段階3でゲーム API ヘッダーを作り直す）。
