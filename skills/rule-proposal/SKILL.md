# 指示の見直しの提案

1. どの Issue・PR で何が起きたかを、利用者に伝える。
2. 原因を見分ける。
   - 指示が足りなかった（そのモデルが知り得なかった約束）→ 指示に加える案を作る。
   - モデルの能力や effort が足りなかった → 再試行の段階を上げる（スキル `dispatch`）。指示の追加は要らない。
   - 仕組みで防げる → 監査・フック・コマンドで防ぐ案を、指示より優先して出す。
3. 案は Issue（ラベル `rule-proposal`）にまとめる。加える文・置き場所（どのファイルのどこか）・加えない場合の影響を書き、週1回の報告にも載せる。同じ種類の問題が繰り返されていれば、それも書く。
4. 承認されたら PR で反映する。新しいセッションから適用する。

- 再試行で、そのワーカーに失敗理由と前提を伝えるのは自由（その作業の中だけの補足）。他の作業にも効く規則にはしない。
