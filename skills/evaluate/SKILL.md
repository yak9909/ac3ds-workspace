# 採点

## 読む物

- `orch.py stamp` が出す、変更したファイル・新しい記録とその確度・symbols の差分の要約・検査の結果。
- 新しい記録の本文（結論・根拠・反証条件）と、ワーカーの `.task/report.md`。
- 一次証拠（IDB・大きなファイル）は読まない。必要なら深い検証に回す。

## 採点表（各項目 0〜1 と、全体の合否）

| 項目 | 見ること |
|---|---|
| 根拠と結論の一致 | 根拠から結論が言えるか。飛躍は無いか |
| 根拠の独立性 | 互いに独立した根拠があるか（疑似C の言い換え2つは独立ではない） |
| 既存の知見との整合 | 既存の記録・symbols と矛盾しないか。矛盾するなら訂正の提案になっているか |
| 確度の妥当性 | 確度が根拠に見合っているか |
| 名前・型の妥当性 | `ac3ds-re/docs/naming.md` に合い、役割を正しく表しているか |

- 合格の基準点は較正で決める（`workers.toml` に記録する）。決まるまでは、どの項目も 0.6 以上を目安にする。
- 点数と判定の理由を、PR のコメントに残す。

## 深い検証に回す物

- 多くの関数から使われる名前・型、HIGH への昇格、上位の格付けの記録の訂正、消化（topics の更新）、ゲーム API ヘッダーに入る物。
- `.claude/agents/reviewer` を起動する（effort は難易度 hard なら high、それ以外は medium）。依頼文には、記録・作業ツリー・IDB コピーの場所を書く。
- 利用枠が足りなければ gpt-6.1-sol に代えて、「Opus 未確認」の Issue を残す。
