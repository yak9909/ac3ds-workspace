# 訂正

1. **判定**: 一次証拠が強い方を採る。格付けは、証拠が同等のときの決め手にだけ使う。
   - 上位の格付けの記録（S・A、または Opus の確認済み）を下位のモデルが訂正する場合は、必ず深い検証に回す。
   - 決着しなければ、両方の記録に「矛盾」の印を付け、実機で確かめる Issue を作る（実機の操作は利用者の承認が必要）。
2. **反映**（採用した場合）: 新しい記録の `supersedes:` に古い記録の ID があることを確かめ、取り込みの仕上げで古い記録を `state: superseded`・`superseded_by: <新しい ID>` にする。
   - IDB と symbols の訂正は、そのワーカーの差分として取り込む。
   - その記録を元にした topics があれば、直すための消化の Issue を作る。
   - `kb.py impact <記録ID>` で、派生リポジトリへの影響を確かめる。
3. **「?」の記録の再解析**: 確認できた場合は、仕上げで `by` を再解析したモデルにし、元の値を `original_by` に残す。誤りなら訂正として扱う。
